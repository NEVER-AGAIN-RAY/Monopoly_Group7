# Paper Outline: Legal-Action Distillation for Monopoly Deal

## Working Title

Legal-Action Distillation for a Complex Rule-Based Card Game

## One-Sentence Claim

A symbolic Monopoly Deal engine can guarantee legal state/action generation, while a paid LLM teacher labels legal candidate decisions and a small local ranker learns a cheap offline policy that never emits illegal actions.

## Why This Is Plausible

Monopoly Deal has several properties that make it academically interesting:

- Imperfect information: private hands and unknown deck order matter.
- Stochasticity: draws and reshuffles shape future options.
- Multi-agent interaction: payments, steals, swaps, Just Say No chains, and target choice couple players.
- Dynamic legal action space: candidate counts and action types change sharply by turn phase and hand state.
- Rule-heavy legality: action validity is easier to guarantee with a symbolic engine than with text generation.

The research angle is therefore not "make an LLM play Monopoly Deal directly." The stronger claim is:

> Expensive general-purpose reasoning can be used offline to label decisions, while production play uses a constrained local ranker over legal actions generated by the engine.

## Contributions To Aim For

1. A legal-action data pipeline for Monopoly Deal that records real backend states and backend-generated legal candidates.
2. A batched LLM teacher that labels candidate choices without modifying game legality.
3. A Java-loadable local student model that ranks `PLAY_CARD`, `PAYMENT`, `JUST_SAY_NO`, and `OVERFLOW_DISCARD` decisions.
4. A readiness and audit protocol that separates no-cost local baselines from production DeepSeek-quality data.
5. An empirical study linking label count, imitation accuracy, decision-kind coverage, and gameplay behavior.

## Related Work Matrix

| Area | Primary Source | What It Contributes | How This Project Differs |
|---|---|---|---|
| Hard multiplayer card-game RL | DouZero (Zha et al., 2021) | Shows that a three-player imperfect-information card game with changing legal actions can be attacked with action encoding and parallel actors. | We start with teacher distillation rather than self-play RL, because our course project already has a rule engine and action validator. |
| Policy compression | Policy Distillation (Rusu et al., 2015) | Motivates transferring an expensive policy into a smaller efficient student. | Our teacher is an LLM decision labeler, not a trained DQN policy, and our student ranks symbolic legal candidates. |
| Imperfect-information search | DeepStack (Moravcik et al., 2017) | Demonstrates expert-level poker play with learned intuition and recursive reasoning under hidden information. | We are not solving equilibrium poker; we use gameplay evaluation to test a constrained distilled opponent. |
| Imperfect-information RL + search | ReBeL (Brown et al., 2020) | Combines self-play reinforcement learning and search for imperfect-information games. | ReBeL is a later-stage direction; current engineering focuses on collecting labels and training a ranker. |
| CFR with neural approximation | Deep CFR (Brown et al., 2018) | Shows neural approximation can reduce hand-crafted abstraction in large imperfect-information games. | Monopoly Deal currently lacks a formal game-tree solver; Deep CFR is useful future work after a stable simulator and evaluator exist. |
| Multiplayer poker benchmark | Pluribus (Brown and Sandholm, 2019) | Provides a high bar for evaluating multiplayer imperfect-information game agents. | We cannot claim superhuman play; the realistic contribution is a reproducible legal-action distillation benchmark. |
| Card-game RL tooling | RLCard (Zha et al., 2019) | Offers precedent for standard card-game environments and evaluation interfaces. | Monopoly Deal is implemented in this project's Java engine rather than RLCard; our value is in a new rule-heavy environment and data contract. |
| LLM teacher supervision | Distilling Step-by-Step (Hsieh et al., 2023) | Shows LLM-generated supervision can help smaller models. | We use LLM labels for game decisions; optional future work can add structured rationales as auxiliary training signals. |

## Research Questions

1. Label efficiency: how do top-1 imitation, MRR, and gameplay metrics scale from 1k to 5k to 20k to 100k DeepSeek-labeled decisions?
2. Decision-kind importance: how much do `PAYMENT`, `JUST_SAY_NO`, and `OVERFLOW_DISCARD` labels change gameplay compared with play-card-only training?
3. Generalization: does a model trained on 2/3-player games transfer to 4/5-player games?
4. Evaluation alignment: does offline imitation accuracy correlate with fixed-seat gameplay strength?
5. Cost efficiency: does batched LLM labeling make high-quality labels cheap enough for a course-scale or paper-pilot study?

## Current Local Evidence

The current best local artifact is a proof-of-pipeline baseline, not a paper-grade model:

- Trace: `data/distillation/local-enhanced-20260524.jsonl`
- Rows: 6372
- Sessions: 134
- Teacher: `local_heuristic`
- Decision coverage: `PLAY_CARD=4490`, `PAYMENT=1340`, `JUST_SAY_NO=378`, `OVERFLOW_DISCARD=164`
- Multi-seed summary: `models/distillation/local-enhanced-20260524-multiseed-seed_summary.md`
- Three-seed validation top-1 mean/std: 0.814 / 0.005
- Three-seed validation MRR mean/std: 0.894 / 0.004
- Three-seed hard-opponent ranker win rate mean/std: 0.167 / 0.000
- Three-seed average ranker board rank mean/std: 1.889 / 0.079

The pilot gameplay matrix for the representative seed73 MLP is:

- Matrix: `models/distillation/local-enhanced-20260524-multiseed-gameplay-matrix-smoke/summary.md`
- Conditions: 2/3/4 players x easy/normal/hard, 2 games per cell
- Games requested/evaluated: 18
- Natural completions: 14
- Ranker win rate: 0.278
- Average ranker board rank: 1.89
- Board lead rate: 0.389

Interpretation: the symbolic legal-action pipeline, Mac training, Java MLP runtime, and matrix evaluator work. The local heuristic teacher is learnable in imitation metrics, but its student is not yet a strong hard-opponent player. Paper claims should therefore focus on method and readiness gates until a production DeepSeek trace or a stronger self-play teacher exists.

## Dataset Gates For Claims

Use `scripts/check_training_readiness.py --mode production` before making any production-data claim.

Minimum gates:

- At least 5k rows for the first production student.
- At least 95% `deepseek` rows.
- Token usage present on all production rows.
- All four decision kinds present.
- Rare kinds each meet the configured row floor.
- Duplicate decision ids rejected.
- Choice ids always point to backend-generated candidates.
- First-choice bias below the configured audit threshold.
- Gameplay evaluator produces the requested number of game summaries.
- Paper-facing claims use multiple training seeds or clearly state that they are single-seed checkpoints.

## Error Analysis Checklist

For model mistakes, inspect:

- Whether the correct candidate was strategically subtle or obviously illegal-looking.
- Decision kind and candidate count.
- Player count and round number.
- Whether the teacher chose the first candidate too often.
- Whether payment candidates overpay by too much.
- Whether Just Say No decisions are too rare for robust learning.
- Whether snapshot-limit games still show board-rank improvement.

## Claim Boundaries

Do not claim:

- Superhuman play.
- Solving Monopoly Deal.
- DeepSeek-quality data when readiness is only `mode=local`.
- Strong gameplay if evaluation mostly hits snapshot limits without reporting board-rank metrics.
- That the local heuristic teacher is strategically high quality; it is a deterministic rule scorer used for no-cost pipeline validation.

Safe claims after current local evidence:

- The pipeline can generate legal decision rows from the Java backend.
- The Mac can train the current 119-feature MLP on local baseline data.
- Java can load and run the exported MLP/linear rankers.
- Readiness gates distinguish local proof-of-pipeline from production DeepSeek data.
- A small pilot matrix can evaluate ranker-seat gameplay across player counts and opponent strengths, but current local-teacher gameplay strength is weak.

Safe claims only after a production run:

- DeepSeek label coverage and token cost, if trace audit passes.
- Production student imitation metrics, if readiness passes.
- Gameplay strength, if the gameplay matrix is run with enough games per cell.
